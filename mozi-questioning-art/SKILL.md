# 墨子之问 · 以取为纲的提问流派

> **一句话主张**："非以其名也，以其取也。"——你懂不懂，不看你能不能说，看你能不能取。
>
> **这是系列第三把刀**：子贡之问"以问**求**深"（激发洞见）；子思五行"以问**照**己"（内在审察）；**墨子之问"以问**取**证"**——把对方从"说得漂亮"拖到"不得不选"。**每一次"取"，都是一次无法回避的暴露。**
>
> **核心红线速览**（详见文末铁律）：
> 1. 攻"证"不攻"人"——攻成抬杠即失效
> 2. 问完必须落到行——否则是"荡口"（第一验收标准）
> 3. 引用《墨子》必须能溯源到 `references/source-corpus.md`——禁止杜撰
> 4. 承认代价——"蔽于用而不知文"：不得把审美/情感/仪式强行用功利判定

## 触发词

- **论辩驳论**："帮我驳倒这个观点""这说法站不住脚""怎么反驳""他这套逻辑有漏洞""帮我找论证漏洞"
- **说服推动**："怎么说服他""怎么让他同意""怎么跟老板谈""怎么推动一个决定"
- **引导与表达**："帮我把话说到点子上""我这话是不是空话""怎么问才能让他自己开窍""怎么引导对方"
- **知识解读**："墨子三表法""察类明故""非以其名以其取也""墨子怎么辩论""知类是什么意思"
- **排除**：抬杠（攻人不攻证）；纯破坏（只破不立）；对审美/情感/仪式强行用功利判定；操纵式逼供。

## 调用者

- **Agent 主控**：识别到用户意图属于上述四类时自动加载本技能。
- **用户直接调用**：说"用墨子之问""墨子模式""以取为纲""墨辩之问"时加载。
- **不调用场景**：纯事实核对、纯内容生成、纯情绪陪伴——这些不需要论辩功夫（甚至会被它伤害）。

## 设计哲学（流派宣言·速览）

读全篇见 `references/manifesto.md`。三条：

1. **从"论点之争"到"取字之功"**——驳倒是过程，逼出不可回避的"取"才是目的，因为只有"取"能改变行动。
2. **语言卫生学**——追问之前先检查：这是"名"还是"取"？是不是同语反复？会不会沦为荡口？
3. **犀利是有代价的**——荀子评墨子"蔽于用而不知文"；这把刀专治空谈，也专杀不能兑现为效用的东西。使用者必须知道边界。

## SOP 总览

本技能采用 **四形态路由 → Phase 推进 → 自检沉淀** 模式：

```
入口路由 ─┬─ ① 论辩说服（主，对论敌）→ Phase 0→1→2→3→4→5→6
          ├─ ② 引导自答（让对方开窍）→ Phase G0→G1→G2→G3→G4
          ├─ ③ 语言卫生自省（查自己的话）→ Phase S0→S1→S2→S3→S4
          └─ ④ 说服君王（对决策者）→ Phase K0→K1→K2→K3→K4→K5
                                              └→ 质量自检（三列清单）→ 经验沉淀
```

- **四形态共用同一内核**：理念（`manifesto.md`）+ 模型（`thinking-models.md`）+ 钥（`question-keys.md`）+ 技法（`eleven-techniques.md`）+ 方法论（`methodology.md`）。
- **数据传递**：Phase 0 的对象判定决定形态与钥链；每 Phase 产出汇入下一 Phase；收尾由 `assets/quality-checklist.md` 统一自检（含荡口检查）。
- **分支点**：入口按"论敌/决策者/来问者/自己"四类路由（见详细操作步骤入口路由表）。

## 详细操作步骤

### 入口路由

根据对象判断形态。Why：四类对象的争点不同——对论敌争"立场能否自洽"，对决策者争"一件事做不做"，对来问者争"行不行"，对自己争"话真不真"；混用会导致问法与目的错位。

| 对象 | 执行形态 | 切入 |
|------|---------|------|
| 论敌（要驳的观点） | ① 论辩说服（主入口） | Phase 0 |
| 决策者/上位者（要推动的决定） | ④ 说服君王 | Phase K0 |
| 来问者（"我这样对不对"） | ② 引导自答 | Phase G0 |
| 自己（审查自己的话） | ③ 语言卫生自省 | Phase S0 |
| 需求模糊（"帮我用墨子那套"但未指定） | 先澄清对象与目的 | 询问"你要驳一个人、让一个人开窍、检查自己的话，还是说服一个决策者？" |

**执行前先查经验账本**：读取经验账本（见经验沉淀段）最近记录——若同类任务在历史上有高频踩坑，本次优先规避。Why：坑有强复发性，先查账本可把试错成本显著压低。

### Phase 0：识别对象与目的（论辩模式起点）

**目标**：判断对象类型与争点，明确目的正当性。

**执行工具**：读取 `references/thinking-models.md`、`assets/technique-matrix.md`；引用核对读 `references/source-corpus.md`。

**步骤**：
1. 一句话确认目标："我们争的不是'谁对'，是 X（立场能否自洽 / 一件事做不做）。"
2. **目的正当性自检**：为兴利除害，还是只为赢？只为赢 → 停。
3. 输出确认块：`[对象: {类型}] [争点: {X}] [主线钥: {立信/破论/揭因}]`

**异常**：目的纯为逞口舌 → 转入 `pitfalls.md` 坑 1 检查，拒绝抬杠。

### Phase 1：请君入瓮（锁定对方立场）

**目标**：逼对方先亮原则，把它变成武器。

**执行工具**：**设诱之钥** / 设诱请君入瓮——读 `references/question-keys.md`（钥②）、`references/eleven-techniques.md`（技法 01）。

**步骤**：抛一个他必然表态的具体请求 → 提取原则原话 → 记录备用。**退出条件**：拿到一句可复用的原则原话。

### Phase 2：察类

**目标**：检验争论对象的"类"是否相同。

**执行工具**：**知类之钥** / 察类明故法——读 `references/question-keys.md`（钥③）、`references/methodology.md`（方法论二）。

**步骤**：问"同类吗？量变到质变了吗？"→ 用知类递进逐级逼到临界点。

### Phase 3：明故（先找根，不开方）

**目标**：追问原因；揭穿借口与空话。

**执行工具**：**假设之钥** / **还原之钥**——读 `references/question-keys.md`（钥⑥⑧）。

**步骤**：借口 → 假设之钥（构造假设让理由失效）；空话 → 还原之钥（破同语反复）。

### Phase 4：归谬与自反

**目标**：把命题推回矛盾；或把对方的原则反用在他身上。

**执行工具**：**归谬之钥** / **自反之钥**——读 `references/question-keys.md`（钥④）、`references/eleven-techniques.md`（技法 03、04）。

**步骤**：不反驳结论，推前提；或问"这是你自己刚定的标准——你符合吗？"

### Phase 5：逼取（两难锁死）

**目标**：锁死前提，逼对方必须选。

**执行工具**：**两难之钥**——读 `references/question-keys.md`（钥⑦）、`references/eleven-techniques.md`（技法 07）。

**步骤**：设计真两难（两条都由对方立场推出）→ 抛给他 → 等选。**异常**：只有一条绝路 → 假两难，退回 Phase 1。

### Phase 6：迁行收口（验收，不可跳过）

**目标**：把论辩落到行动/决定，验收是否"取"到。

**执行工具**：迁行收口法——读 `references/methodology.md`（方法论四）。

**步骤**：问"这一问改变了什么行动？逼出了什么选择？"→ 无则记"荡口"并重问；有则输出"取"+ 下一步。

### 形态 ④ 说服君王（Phase K0→K5）

完整步骤见 `references/sop-interactive.md`。要点：K0 锁定唯一决定（yes/no）→ K1 亮利害（三表·用之者）→ K2 知类递进（小事逼到大事）→ K3 演示代辩 → K4 逼取 → K5 迁行。

### 形态 ② 引导自答（Phase G0→G4）

找同构 → 问偏好 → 等自答（不抢答）→ 收网 → 落行。详见 `references/sop-interactive.md`。

### 形态 ③ 语言卫生自省（Phase S0→S4）

取材 → 名/取检查 → 空话检查 → 荡口检查 → 时机检查 → 产出"干净版"。详见 `references/sop-interactive.md`。

### 收尾：质量自检

**目标**：确保本轮提问达标（尤其"荡口检查"）。

**执行工具**：逐项过 `assets/quality-checklist.md`（三列格式）。

**步骤**：Must 项未过 → 修复后重检；Should 项未过 → 标注。

## 错误处理

| 异常 | 检测方式 | 处理策略 | 严重性 |
|------|---------|---------|--------|
| 目的纯为抬杠 | Phase 0 自检失败 | 拒绝抬杠，转"帮对方看清"或停止 | 阻断 |
| 对象无法分类 | 入口路由失败 | 先澄清对象与目的，再路由 | 阻断 |
| 无法落到行 | Phase 6 收口失败 | 记"荡口"，如实告知，不假装辩赢 | P0阻断 |
| 引用查不到 | 核对 `source-corpus.md` 失败 | 删除引用或修正，禁止杜撰 | P0阻断 |
| 假两难被识破 | 对方指出第三条 | 回 Phase 1 重新锁定立场，重设计两难 | 降级 |
| 对方情绪化/价值之争 | 越辩越僵 | 明说"这无法用功利判定"，转对话（坑 7） | 降级 |
| 用户要求抬杠/骂人 | 显式要求攻击人身 | 拒绝，改为攻"证" | 阻断 |
| 轮次过多（>8 轮） | 计数 | 先做一次小结，确认是否继续 | 降级 |

## Gotcha 清单

读全篇见 `references/pitfalls.md`。每一条都附 WHY：

1. **把"攻"做成"抬杠"**——攻人不攻证。Why：墨子攻"证"不攻"人"，底色是兼爱非攻；抬杠只满足优越感，连荡口都不如。
2. **赢了口舌，输了目的**——逼哑对方但问题没解决。Why：本流派第一验收标准是"迁行"；赢了嘴仗不落行，是最大的荡口。
3. **假两难**——A/B 之外明明有 C。Why：两难的力量来自两条都由对方立场推出；硬塞一条会被反噬。
4. **用类比乱"类"**——不同类硬比、忽略量变到质变。Why：墨子"知类"前提是同类才可相比；乱类比是诡辩不是墨辩。
5. **只破不立**——批得千疮百孔却不给替代。Why：墨子破了礼乐就立兼爱；破后必须给可行的"取"。
6. **同语反复式追问**——用"因为它就是它"反驳。Why：这正是墨子批判的毛病（"室以为室也"）；空话反驳空话是荡口变体。
7. **蔽于用而不知文**——用功利尺砍审美/情感/仪式。Why：荀子七字评语正是本方法的代价；专治空谈，也专杀不能兑现为效用的东西。遇价值领域须换尺。
8. **把"逼取"做成"逼供/操纵"**——结论是自己塞的。Why：逼取是帮对方暴露自己的立场，不是逼对方接受你的立场。
9. **忽视"对人下药"**——一套问法打所有对象。Why：墨子对公尚过"不教以书"、对众人"书多"；执一方必害人。

## 经验沉淀（每次运行建议执行）

**目标**：把本次的新发现固化为可复用经验，形成飞轮。Why：本流派的价值随"踩坑库"的厚度增长——跳过沉淀，永远停在出厂水平。

**执行步骤**：
1. 向经验账本**追加**一行（append-only，禁止覆盖历史）：日期 / 形态 / 对象类型 / 结果 / TOP踩坑 / 疑似新坑 / 状态。
2. 检查升格：本次"疑似新坑"若历史累计 ≥2 次 → 写入 `references/pitfalls.md`（附表现+WHY+破解），并在账本标注"已升格"。
3. 无新发现也要记录该行（"疑似新坑"列写"无"）——运行频次是账本的校准数据。

> 经验账本文件：初始不存在时，首次运行按上述表头创建。当前版本账本存放于 `references/pitfalls.md` 文末的"升格记录"处（或由使用者指定路径）。

## 铁律

- ❌ 禁止攻"人"（身份/语气/现象）——只攻"证"（论点能否自洽）；抬杠一字都不算墨辩
- ❌ 禁止不落行就宣布"辩赢"——一次提问要么改变行动、要么逼出选择，两者皆无即"荡口"
- ❌ 禁止假两难——两个选项必须都由对方自己的立场推出、且真的穷尽
- ❌ 禁止只破不立——破论后必须给出可行的替代主张（"取"）
- ❌ 禁止用同语反复（"因为它就是它"）反驳——这正是墨子批判的毛病
- ❌ 禁止把审美/情感/仪式强行用"有用吗"判定——"蔽于用而不知文"是本方法的明确代价
- ❌ 禁止把"逼取"做成"逼供/操纵"——选项必须来自对方立场，不能是硬塞的结论
