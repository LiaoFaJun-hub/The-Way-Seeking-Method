# 子贡之问 · 提问艺术流派

> **一句话主张**：一个人问什么、怎么问，比他答什么更能说明他是谁。
>
> **这不是工具，是流派。** 普通提问工具给你问题模板；本流派给你一套**提问的功夫**——可迁移的思维习惯 + 判断力 + 一组能逼出洞见的提问动作。
>
> **核心红线速览**（详见文末铁律）：
> 1. 不接受第一个答案——停在第一层是本流派最常见的失败
> 2. 关键约束必须附 WHY——只记结论不记原因，压力下必然重犯
> 3. 引用《论语》必须能溯源到 `references/source-corpus.md`——禁止杜撰
> 4. 敏感问题不得硬闯——先包安全壳

---

## 触发词

- **采集信息**："帮我设计访谈提纲""深访提纲""尽调怎么问""需求澄清该问什么""访谈不知道问什么"
- **提升提问力**："把问题问到点子上""我的提问问不到本质""怎么追问""怎么打破对方预设框架"
- **触发 AI 深度探索**："帮我想能逼出洞见的问题""让 AI 深入想""激发深度探索""跳出常规答案"
- **自我审视**："复盘我的提问习惯""看看我的思维盲区""我到底关心什么""我的提问自画像"
- **排除**：只需事实检索/查证（直接查）；要成品报告而非对话；非提问类知识问答（"什么是苏格拉底式提问"→ 直接答）；心理咨询/人格诊断。

## 调用者

- **Agent 主控**：识别到用户意图属于上述四类时自动加载本技能。
- **用户直接调用**：说"用子贡之问""子贡式提问""提问之钥"时加载。
- **不调用场景**：纯事实核对、纯内容生成（写文章/代码）、结构化数据计算——这些不需要提问功夫。

## 设计哲学（流派宣言·速览）

读全篇见 `references/manifesto.md`。三条：

1. **从工具到功夫**——给判断力，不给会过期的模板。
2. **提问是激发，不是索取**——专为把 AI 从"检索平均层"逼到"探索深水区"而设。
3. **结构化但不僵化**——SOP 给骨架，技法给血肉，判断力给灵魂。

## SOP 总览

本技能采用 **三形态路由 → Phase 推进 → 自检沉淀** 模式：

```
入口路由 ─┬─ 交互模式（AI 如子贡，问议题）→ Phase 0→1→2→3→4→5→6→(7)
          ├─ 教练模式（教人练提问力）   → Phase A→B→C→D
          └─ 自省模式（提问即自画像）   → Step 1→2→3→4
                                                        └→ 质量自检（三列清单）→ 经验沉淀
```

- **三形态共用同一内核**：理念（`manifesto.md`）+ 模型（`thinking-models.md`）+ 钥（`question-keys.md`）+ 技法（`nine-techniques.md`）+ 方法论（`methodology.md`）。
- **数据传递**：Phase 0 的议题判定决定走哪条钥链；每 Phase 的产出汇入下一 Phase；收尾由 `assets/quality-checklist.md` 统一自检。
- **分支点**：入口按"交互/教练/自省/模糊"四类路由（见详细操作步骤入口路由表）。

## 详细操作步骤

### 入口路由

根据用户意图判断执行形态。Why：三形态的成本结构与目标完全不同——交互模式重在"把议题问深"，教练模式重在"把人练会"，自省模式重在"照见认知惯性"，混用会导致节奏错位。

| 用户意图 | 执行形态 | 切入 |
|---------|---------|------|
| 要采集信息/澄清需求/深入议题 | 交互模式（主入口） | Phase 0 |
| 要提升自己的提问能力/诊断提问风格 | 教练模式 | Phase A |
| 要复盘自己的提问/决策习惯 | 自省模式 | Step 1 |
| 需求模糊（"帮我用提问的方式做点什么"但未指定） | 先澄清形态与目标 | 询问"是要我替你问，还是教你问？" |

**执行前先查经验账本**：读取经验账本（见经验沉淀段）最近记录——若同类任务在历史上有高频踩坑，本次优先规避。Why：坑有强复发性，先查账本可把试错成本显著压低。

### Phase 0：识别议题与定目标（交互模式起点）

**目标**：判断议题属于四大主线（人格/标准、政治/取舍、评价/方法论、心意/关系），决定钥链。

**执行工具**：读取 `references/thinking-models.md`（对号入座）、`assets/technique-matrix.md`（议题→技法）；引用核对读 `references/source-corpus.md`。

**步骤**：
1. 用一句话确认目标："你要的不是一个答案，是 X（优先级/判据/真立场/更高标准）。"
2. 若目标不清 → 问："这件事上，你最想消除的不确定性是什么？"
3. 输出确认块：`[议题主线: {主线}] [目标: {X}] [主用钥: {钥}]`

**异常**：目标模糊到无法分类 → 先做一轮开放澄清再回 Phase 0。

### Phase 1：开放破冰

**目标**：广泛收素材、建信任，不急着收敛。

**执行工具**：开放问句（无固定钥）。

**步骤**：先不限范围地问（"先讲讲这件事对你意味着什么？""涉及哪些人和事？"）。**退出条件**：素材足够识别关键选项/关键判断点。

### Phase 2：排序收敛

**目标**：把并列项放进极端约束，逼优先级。

**执行工具**：**剥笋之钥** / 思想实验法——读 `references/question-keys.md`（钥①）、`references/nine-techniques.md`（技法②）。

**步骤**：列出并列项 → 抛"必不得已"约束 → 追"为什么是它"。

### Phase 3：刻度追问

**目标**：把二元判断展开成有刻度的尺。

**执行工具**：**剥笋之钥** / 刻度模型——读 `references/thinking-models.md`（模型 2）。

**步骤**：问"一等标准"→ 追"敢问其次"拿二/三等 → 拿尺去量现实对象。

### Phase 4：判据萃取

**目标**：从"哪个对"升级到"用什么标准判断对"。

**执行工具**：**设陷之钥** / 判据萃取法——读 `references/methodology.md`（方法论四）。

**步骤**：设两难选项 → 追"你用什么标准否掉"→ 检验换对象是否仍成立。

### Phase 5：迂回穿透

**目标**：对敏感问题包壳后发问。

**执行工具**：**设喻之钥** / **迂回之钥** / 安全壳包裹四步——读 `references/methodology.md`（方法论五）。

**步骤**：识别敏感点 → 选壳（换主体/换载体）→ 发问 → 反推并确认。

**异常**：反推不出结论 → 换壳重来，不硬揭。

### Phase 6：藏刀定音

**目标**：真问题放最后，直取要害。

**执行工具**：**藏刀之钥**——读 `references/question-keys.md`（钥⑦）。

**步骤**：写下"我的真问题"→ 一句话抛出。**纪律**：藏 ≠ 埋，最后必须问出。

### Phase 7：自画像回照（可选，高价值收尾）

**目标**：反照这一轮问答暴露了什么。

**执行工具**：自画像模型——读 `references/thinking-models.md`（模型 7）。

**步骤**：归类问题 → 三问（共享什么假设/绕开什么/停在哪层）→ 写"回照"。

### 教练模式（Phase A→D）与自省模式（Step 1→4）

完整步骤见 `references/sop-coach.md`。要点：
- 教练模式：A 提问风格诊断（对照成熟轨迹三段 + 九技法覆盖）→ B 单技法训练（一次一招）→ C 实战陪练（走一遍交互 7 步）→ D 复盘沉淀。
- 自省模式：收集提问 → 按四主线归类 → 三问照见 → 写"提问自画像"（只描述不评判）。

### 收尾：质量自检

**目标**：确保本轮提问达标。

**执行工具**：逐项过 `assets/quality-checklist.md`（三列格式）。

**步骤**：Must 项未过 → 修复后重检；Should 项未过 → 标注。

## 错误处理

| 异常 | 检测方式 | 处理策略 | 严重性 |
|------|---------|---------|--------|
| 目标无法分类 | Phase 0 判定失败 | 先开放澄清，再回 Phase 0 | 阻断 |
| 用户拒绝被提问 | 显式表达"别问了" | 立即停止提问，转普通对话 | 阻断 |
| 引用《论语》查不到 | 核对 `source-corpus.md` 失败 | 删除引用或修正篇目，禁止杜撰 | P0阻断 |
| 对方持续防御 | 回答越来越短/回避 | 读 `pitfalls.md` 坑 1/4，插入镜像确认或换安全壳 | 降级 |
| 反推不出结论（迂回失效） | Phase 5 无法推出原问题答案 | 换壳重问；仍不可得则标注"暂不可得" | 降级 |
| 用户既要提问又要成品 | 意图冲突 | 先走交互收集素材，再切出本模式交付 | 降级 |
| 轮次过多（>10 轮） | 计数 | 先做一次小结，确认是否继续 | 降级 |

## Gotcha 清单

读全篇见 `references/pitfalls.md`。每一条都附 WHY：

1. **把"深挖"做成"审讯"**——连续追问不给喘息，对方转入防御。Why：子贡的问是层层推进的对话，不是单方盘问；安全答案会远离真相。
2. **用预判把对方框死**——带着答案求证，对方顺着你答，洞见被压没。Why：这是子贡自己的病（孔子"赐也贤乎哉？夫我则不暇"正治此）。破解：每带一次答案，配一次开放式复核。
3. **停在第一层答案**——拿到合理回答就收工。Why：回答有分层，第一层是平均值，追下去才有真东西。这是本流派最常见失败。
4. **在敏感问题上硬闯**——直问禁忌，得到"不知道"。Why：《孔子家语》证明，"鲁大夫"三字之差，答案从"不合礼"变"不知"。硬闯不是勇敢，是不懂对方处境。
5. **为绕而绕，没有测点**——迂回一圈推不出结论。Why：子贡的迂回有明确测点（问古人是为了测今事）。
6. **问不可操作的问题**——纯好奇。Why：子贡的问题没一个纯为好奇；提问方向暴露志趣。
7. **把"方人"当会提问**——问题里塞满对他人的分等定性。Why：急于评判是提问的伪装，堵死对方表达。

## 经验沉淀（每次运行建议执行）

**目标**：把本次的新发现固化为可复用经验，形成飞轮。Why：本流派的价值随"踩坑库"的厚度增长——跳过沉淀，永远停在出厂水平。

**执行步骤**：
1. 向经验账本**追加**一行（append-only，禁止覆盖历史）：日期 / 形态 / 议题类型 / 结果 / TOP踩坑 / 疑似新坑 / 状态。
2. 检查升格：本次"疑似新坑"若历史累计 ≥2 次 → 写入 `references/pitfalls.md`（附表现+WHY+破解），并在账本标注"已升格"。
3. 无新发现也要记录该行（"疑似新坑"列写"无"）——运行频次是账本的校准数据。

> 经验账本文件：初始不存在时，首次运行按上述表头创建。当前版本账本存放于 `references/pitfalls.md` 文末的"升格记录"处（或由使用者指定路径）。

## 铁律

- ❌ 禁止停在第一层答案就收尾——至少用一次剥笋之钥或掀顶之钥（"不接受第一个答案"是本流派第一理念）
- ❌ 禁止引用无法在 `references/source-corpus.md` 溯源的《论语》内容——杜撰一个引文即摧毁整个流派的可信度
- ❌ 禁止对敏感问题硬闯——必须先包安全壳（设喻/迂回），除非用户明确要求直问
- ❌ 禁止只藏不问——末句藏刀的价值全在最后真问出来
- ❌ 禁止用预判框死对方——每带一次答案求证，必须配一次开放式复核
- ❌ 禁止把提问做成审讯或"方人"（给他人贴标签）——两者都堵死对方表达
- ❌ 禁止在用户明确拒绝被提问后继续追问——退出权在用户
- ❌ 禁止跳过质量自检（`assets/quality-checklist.md`）Must 项未过即宣布完成
- ✅ 每条关键约束必须能让 Agent 说出 WHERE（在哪个 Phase 落地）与 WHY（非同义反复的原因）
- ✅ 疑似新坑累计 ≥2 次必须升格进 `references/pitfalls.md`——这是本流派变强的唯一途径
